# 库管理规范 · 嘲讽库 / 梗库 / 用户输入

> 三个库，一套规范。核心是**标明来源**——不然自撰的和抄来的混在一起，库就不可信。

---

## 一、统一字段

所有条目都有这七个基础字段：

```json
{
  "id": "taunt-0001",
  "kind": "taunt",
  "source": "authored",
  "source_url": "",
  "contributor": "",
  "added_at": "2026-11-05",
  "verified": false,
  "weight": 1.0
}
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `kind` | `taunt` / `meme` | 嘲讽模板 / 梗 |
| `source` | `scraped` / `authored` / `adapted` / `user` | 见下表 |
| `source_url` | URL 或空 | 抓来的必须填 |
| `contributor` | 人名或空 | 用户输入的填 |
| `verified` | true / false | 有没有核对过 |
| `weight` | 0–1 | 计分或选用时的权重 |

---

## 二、来源与权重（这张表是核心）

| source | 含义 | verified | weight | 说明 |
|---|---|---|---|---|
| `scraped` | 从网上抓的原文 | true | **1.0** | 必须带 `source_url` |
| `authored` | 自己按机制写的 | — | **0.9** | 没出处，但机制清楚 |
| `adapted` | 抓来的改写过 | — | **0.8** | 必须填 `source_url` 并注明"改编自" |
| `user` + 已验证 | 用户提供的，核对过 | true | **0.7** | 能联网核实才行 |
| `user` + 未验证 | 用户提供的，没核对 | false | **0.4** | **必须在输出里标明** |

**为什么用户的权重最低**：不是不信，是**没法核**。
一个没出处的说法，和一条能点开链接的原文，可信度本来就不同。

---

## 三、用户输入的规矩

**一、不拒绝，但必须打标。**
用户给的好句子照收，只是 `source: "user"` + `verified: false`。

**二、用到时必须在输出里说明。**
不能把用户提供的话当成"网络通用说法"卖给下一个读者。

**三、能核就核。**
如果用户给的是"某本书里的一句话"，我去查证 → `verified: true`、`weight` 升到 0.7。

## 四、嘲讽库的独有字段

```json
{
  "band": "80-90",
  "style": "绿茶",
  "mechanism": "借第三方的刀",
  "target": "自评",
  "tpl": "……{score}……{self}……",
  "slots": ["score", "self"],
  "note": "什么时候用、怎么改"
}
```

`style` 只能是：雌小鬼 / 绿茶 / 毒舌 / 冷淡 / 阴阳怪气 / 钱钟书式 / 鲁迅式 / 网络式

---

## 五、梗库的独有字段

```json
{
  "meme": "鼠球",
  "kind": "自创",
  "status": "常青",
  "origin": "本文",
  "peak": "",
  "meaning": "把老鼠当球踢",
  "note": "不依赖网络热点，不过时"
}
```

`status` 只能是：`常青` / `过时` / `新兴`
**这三个值随时间变**——所以要定期重估，重估记录写进 `checked_at`。

---

## 六、增长方式

| 库 | 现在 | 怎么涨 |
|---|---|---|
| 嘲讽库 | 57 条 | 抓评论区 + 用户输入 + 自撰 |
| 梗库 | 10 条 | **定时从热点抓**，每月重估 status |
| 用户输入 | 0 条 | 作者/读者提供，标来源 |

**嘲讽库增长最快也最值钱**，因为它是用户体验的最后一公里。

---

## 七、一条自我约束

库越大，越容易变成"梗的杂货铺"——
什么都有，什么都不准。

所以每次扩充后要问一句：

> **新加的这条，能在一个具体缺陷上比旧的更狠吗？**

不能，就是噪音。
