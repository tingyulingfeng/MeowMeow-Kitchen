# 反馈接口 · 用户侧三个空

> 用户只填三行，交上来即记。按时间顺序写成文本，不留 ID，不分项打分。

---

## 一、用户侧（2026-11-05 定稿）

```
嘲讽够不够力: 
哪里面子没给够: 
想说的话: 
```

**只有第一个必填。**

`嘲讽够不够力` 只认三个词：**不够 / 刚好 / 过了**

---

## 二、权重是反着来的（关键）

作者原话：

> **力度刚好 +0.2，力度过了 +1（都说了往死里嘲讽，用户脸皮厚着呢）**

| 填的 | 权重 | 含义 |
|---|---|---|
| 不够 | **0** | 白写了，没扎到 |
| 刚好 | **+0.2** | 有效，但还留了面子 |
| **过了** | **+1.0** | **成功。目标就是把人气到** |

**注意：「过了」不是越界，是满分。**

我一开始把「过了」当成"骂过头了要扣分"，完全搞反了——
**这个工具的目的就是气人。用户说过了，说明真的气到了。**

## 四、统计怎么看

```
嘲讽力度： {'过了': 1}
「过了」占比 100%   ← 这是目标，越高越好
✓ 「过了」占 100% —— 力度到位
```

判读：

| 情况 | 结论 |
|---|---|
| 「够了」占比 ≥50% | 力度不足，骨架要换 |
| 「过了」占比 ≥50% | 力度到位 |
| 两者都不高 | 偏温和，还能再狠 |

**「不够」超过一半，就是这套骨架有问题的信号。**

## 五、被删掉的字段，以及为什么

| 字段 | 删于 | 理由 |
|---|---|---|
| `report_id` | 2026-11-05 | 给机器对账用的，用户不需要知道 |
| `服不服` | 2026-11-05 | 在问对分数的态度——但他不是评审，是读者 |
| `哪项分不认` | 2026-11-05 | 要求他懂评分结构，门槛太高 |
| `想反驳的一句` | 2026-11-05 | 和「哪里面子没给够」重复 |

**剩下的三个空，都是读者答得出来的。**

---

## 六、一条不能破的规矩

**反馈不能直接改分。**

用户说"不够力"，那是说嘲讽，不是说分数。
分数必须由规则算，不能由情绪改。

反馈只能改两样：**骨架的取舍** 和 **判据的长期校准**。
