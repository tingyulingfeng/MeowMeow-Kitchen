# 反馈接口 · 报告末尾的回路

> 用户侧只填四个空，交上来即记。
> **不需要 report_id，不需要分项打分——按时间顺序记成文本就行。**

---

## 一、用户侧：四个空（2026-11-05 定稿）

```
嘲讽够不够力: 
哪里面子没给够: 
想反驳的一句: 
想说的话: 
```

| 空 | 填什么 |
|---|---|
| **嘲讽够不够力** | 不够 / 刚好 / 过了 |
| 哪里面子没给够 | 自由写，哪一句让你不舒服、或者哪里下手太轻 |
| 想反驳的一句 | 抄一句你不认的 |
| 想说的话 | 随便 |

**其余留空也行，只有第一个必填。**

---

## 二、接收端：一条命令

```bash
python lt_feedback.py intake 用户填好的.txt
```

同时写两个地方：

| 文件 | 用途 |
|---|---|
| `反馈记录.txt` | **按时间顺序，人能直接读**，只追加 |
| `反馈表.jsonl` | 结构化，用来算骨架胜率 |

### 文本记录长这样

```
反馈记录（按时间顺序，只追加）
========================================================

[2026-11-05 01:22:27]  fb-0001
  嘲讽够不够力：不够
  哪里面子没给够：分数那一段，你说我自己填的分，这个戳到了
  想反驳：「你把小伙伴砌进墙里了」——我承认
  想说的：别的还行，就是太轻了
```

---

## 三、力度三档怎么影响骨架

| 填的 | 含义 | 对骨架 |
|---|---|---|
| **不够** | 白写了 | 胜率 +0 |
| **刚好** | 有效 | 胜率 +1 |
| **过了** | 可能骂到了人 | 胜率 −0.5，并检查是不是越界 |

统计里会算一个「刚好占比」——
**低于 50% 说明力度控制有问题**，要么太软要么太狠。

---

## 四、为什么去掉了原来的字段

原来有 `report_id`、`服不服`、`哪项分不认`。
作者删掉了它们，只留力度和「面子」。

理由（我的理解）：

- **`report_id` 是给机器对账用的，用户不需要知道**
- **`服不服` 是在问他对分数的态度——但他不是评审，他是读者**
- **`哪项分不认` 要求他懂评分结构，门槛太高**

**留下的两个问题，都是读者答得出来的：**
「够不够力」是感受，「哪里没给够面子」是具体位置。

这比问"你觉得这个分对不对"有用得多。

---

## 五、一条不能破的规矩

**反馈不能直接改分。**

用户说"不够力"，那是说嘲讽，不是说分数。
分数必须由规则算，不能由情绪改。

反馈只能改两样：**骨架的取舍** 和 **判据的长期校准**。

| 要什么 | 最小实现 |
|---|---|
