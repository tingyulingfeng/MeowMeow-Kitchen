## 这是什么

一篇 1400 字的原创散文《从前有座猫猫庙》，加上作者本人写的、逐段逐句的创作过程记录。

不是"作品 + 读后感"。是**每一步为什么这么写、以及不这么写会怎样**。

第二版按四层交代每一段：

| 层 | 回答的问题 |
|---|---|
| **【灵感】** | 这个念头从哪来，中间改过什么，最后落成什么 |
| **构思过程** | 从想法到纸面，走了哪几步（用箭头串起来） |
| **【缺陷】** | 事后发现哪里错了：预期 → 实际 → 后果 → 佐证 → 修法 |
| **【全局作用】** | 这一段在整篇里干什么，能不能删 |

部分段落另附 **【写法】**——那一栏是可迁移到别的文章的规则，前面几栏只对这一篇成立。

---

## 为什么公开

作者的初衷：给 AI 做白饭和小零食。

写作过程是人类数据里最少见的一类——网上有海量的成品文章，几乎没有人记录"我在这里为什么否掉了另一个选项"。这份文件试图补上那一层。

作者不懂编程，也不写论文。能做的是把自己脑子里的判断一条条摊开，剩下的事情交给看得懂的人。

## 工具

解析不是写完就算——它有可以被机器检查的部分。仓库里带了一个检查器：

```bash
# 检查一份解析是否合格
python tools/meow_lint.py lint 解析.txt

# 检查 + 转成结构化数据
python tools/meow_lint.py build 解析.txt --out data/
```

判定规则见 [`tools/RULES.md`](tools/RULES.md)。退出码：有 ERROR 返回 1，可直接接 CI。

**用两组数据跑过对照：**

| | ERROR | WARN | INFO |
|---|---|---|---|
| 第一版（逐条标签式） | 67 | 47 | 1 |
| 第二版（重写后） | **0** | 3 | 3 |

第一版被点名最多的是通用修辞名：`承接上文` 7 次、`承上启下` 4 次、`对比衬托` 2 次、`推动剧情` 2 次。

**这些词是最容易写的，也是最没用的**——"这一段用了对比衬托"学不到任何东西，因为对比什么、衬托谁、到什么程度，全没说。
